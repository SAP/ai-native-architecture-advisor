Chapter:01
Why an architecture advisor?↓

This project is dedicated to initial high-level solution design for architects and business teams. The Advisor asks only the questions that materially affect the architecture, separates confirmed facts from assumptions, and explains the value and trade-offs of each change. Keeping a suitable existing design is a valid recommendation.

2.1 — The workflow↓
2.1: The workflowDescribe → Review
01
Describe

Start with the business problem

Bring the actors, the desired outcome and any constraints you already know. You do not need a complete technical design.

02
Explore

Explore the options together

The Advisor maps the scenario to SAP reference architectures and explains each option, strongest fit first.

03
Decide

Weigh the trade-offs

Confirmed facts stay separate from assumptions. Keeping a suitable existing design is a valid call.

04
Build

Build the solution brief

Generate a visual HTML report, the brief, and a reasoning log. Continue the conversation to revise.

05
Review

Human architect validation

Validate the draft against current SAP documentation, your landscape, entitlements and security requirements before you use it.

4.2: Honest by designAssist, not replace

A draft for human review, not an approved design.

This is initial high-level solution design for solution and enterprise architects and business teams. It is not a PRD, a functional specification or a detailed technical design. Field-level requirements and configuration are left for later design.

AI can hallucinate services, capabilities, integrations and references. Check recommendations against current SAP documentation and your actual landscape, availability, entitlements and security requirements before you use the proposal.
